## 2. 主结论：两个臂在车辆上都掉 AP，但病因完全不同

这是本次 debug 最重要的一条。只看 AP 会把 A1 和 A2 归为同一种失败，
oracle 分解证明它们是两种病，因此修法也必须不同。

**A1 砍掉的是天花板。** 车辆 oracle 从 11.3907 掉到 7.6704（−32.7%），
排序效率 0.549 分毫未动。全局 IoU-aware 分类目标把车的提案本身做坏了——
它拿 2D IoU 当分类目标，奖励"大致对"的框，而 strict 3D AP 只认深度上钉死的框。
分类目标的软化对占绝对多数的车是净损失。

**A2 砍掉的是效率。** 车辆 oracle 基本守住（11.3907 → 11.0994，−2.6%），
排序效率从 0.549 掉到 0.451（−17.9%）。SEIT 没有伤害提案质量，它伤害的是排序。

效率下降的**主导解释**（推断，非直接测量）是第 5 节缺陷 5：
A2 跑的那版放置规则只查中心距离，允许移植物完全压住宿主场景中已标注的目标，
把标注框下的真实事件擦掉，从而制造标签噪声，使模型对车的置信度不再可靠。
该缺陷由代码审查发现并已修复；A3 的 `max_coverage_of_existing: 0.15`
就是对这一解释的受控检验——若效率回到 0.549 附近，解释成立。

**行人两个臂都赢，且赢法不同。** A1 把行人排序效率从 0.102 抬到 0.282（近三倍），
这正是 C77 预测的"打分修复"；但它同时把行人天花板只抬到 2.5632。
A2 把行人天花板从 1.8659 抬到 3.3273（+78%），
这是提案质量的真实改善，是 C77 里"必须来自框质量/泛化"的那部分。
两者正交，这构成 A3 的全部依据。

**一个反直觉事实必须记下：A1 的框质量最好，AP 最差。**
A1 的 `mean_matched_iou_3d` 0.04388 和 recall@2D 0.70 = 0.3415 都是三臂最高，
strict 3D AP 却最低。任何"框做准了 AP 自然会涨"的直觉在这个数据集上不成立，
必须用 oracle 分解而不是框质量指标来判断一个机制是否有害。

## 3. 被否决的假设

每条都是先有可证伪预测、再跑测量、最后按数字裁决。列出否决理由是为了防止重复排查。

### H1 — 分数尺度被 0.1 阈值截断 → **否决**

预测：A1 把分数压缩，正确定位的车掉到解码阈值 0.1 以下被评测器丢弃。
测量：把官方视图阈值降到 0.0 重跑诊断。
结果：车辆 4.2104 → 4.2402（+0.03，噪声级），行人反而 0.7218 → 0.6254 下降。
裁决：被丢弃的框确实存在，但把它们放回来不涨 AP——它们排在假正例后面。
问题不是截断，是排序。

### H3 — 3D 几何质量退化 → **否决**

预测：A1 的车辆 3D AP 掉是因为深度精度变差。
测量：比较 `mean_matched_iou_3d`。
结果：R1 0.03443 → A1 0.04388，不降反升 27%。

### H5 — 缺少 NMS，重复框被记为假正例 → **否决**

预测：`group_num=11` 下多组可以认领同一目标，EvStereo3D 有 3D NMS 而我们没有。
测量：对 A2 落盘预测施加 EvStereo3D 同款 3D NMS（IoU 0.25）后重跑冻结评测器，
收据 `reports/epst4d_v3/a2_seit/nms_probe/`。
结果：Veh 5.0090 → 5.0383，Ped 0.6686 → 0.6756。两个方向都在噪声内。
裁决：一对一匹配确实让抑制变得多余，缺 NMS 不是 AP 缺口的来源。

### H7 — 行人挤占车辆的输出预算 → **否决**

预测：SEIT 抬高行人分数后，行人检出占掉有限的输出槽位。
测量：`tools/epst4d_v3/probe_detection_budget.py` 按类统计检出数与分数分布。
结果：车辆检出确实减少、行人增加，但两类的 `min_score` 都精确停在 0.1，
说明限制检出的是分数阈值而不是 top-k 预算；同时车辆中位分上升。
裁决：不是槽位竞争，是分数分布变尖锐把边缘检出推到了阈值以下。

### H8 — 分数分布变尖锐导致正确检出被阈值切掉 → **否决**

这是 H7 的自然后继：既然分布变尖，降阈值就该救回来。
测量：A2 阈值降到 0.0 重跑。
结果：Veh 5.0090 → 4.7199，Ped 0.6686 → 0.5993，两类都**更差**。
裁决：0.1 阈值没有在切有价值的检出。H1 与 H8 从两个方向撞上同一堵墙，
可以合并成一条规则：**本流水线的 AP 缺口不在解码阈值上，不要再动它。**

## 4. 仍未定论

### H4 — 高质量 3D IoU 尾部变薄 → **OPEN，证据不完整**

假设：均值 3D IoU 上升可以掩盖尾部变薄，而 strict AP 完全活在尾部。
为此给诊断加了 `recall_by_iou_3d_threshold`（按 3D IoU 分档统计被覆盖真值的占比）。

**当前只有 A2 落盘了这个指标**，R1 与 A1 的补测（`diag_tail/`）在用户叫停时
只跑到 2000 query，没有产出 `C2_BOTTLENECK.json`。因此**没有可比基线，H4 不能裁决**。

A2 的尾部读数（留档）：

| 类 | mean 3D IoU | ≥0.25 | ≥0.50 | ≥0.70 |
|---|---|---|---|---|
| Vehicle | 0.3454 | 56.5% | 35.7% | 11.1%（2607/23412） |
| Pedestrian | 0.0591 | 10.5% | 3.8% | 0.26%（15/5701） |

行人在 0.70 档只有 15 个真值被覆盖，这本身说明 strict 3D 行人 AP 的上限

## 5. 排查中发现并修掉的实现缺陷

| # | 缺陷 | 影响面 |
|---|---|---|
| 1 | `_tiny_overfit` 读 `config["experiment"]["output_dir"]`，而所有 config 定义在 `training` 下 | **所有臂**（含 R1）的 tiny-overfit 预检一律抛 `KeyError`，C40 的修复因此从未生效 |
| 2 | SEIT 移植未重新锚定时间戳 | `CausalEventVoxelizer` 报 "future event"，移植事件晚于宿主 query 时刻，破坏因果性 |
| 3 | SEIT 在 GPU 张量上直接调 `numpy()` | 训练期崩溃 |
| 4 | SEIT 假定 target 一定有 `supervision_contract` | dataloader 实际下发 `official_unfiltered` target，字段集不同，崩溃 |
| 5 | SEIT 放置只查中心距离 `min_center_distance_px` | 移植物可以完全压住已标注目标，擦掉标注框下的真实事件；已改为 `max_coverage_of_existing` 覆盖率守卫 |
| 6 | 供体池顺序扫 manifest（manifest 按序列排序） | v1 池 400 个行人供体只来自 12 个 `sequence_id`（5 个 DSEC 母序列），多样性不足以支撑高剂量粘贴；改为按序列分层采样后，v2 为 841 个行人供体、43 个 `sequence_id`（21 个母序列） |

缺陷 1 值得单独记账：它是一个**测量装置缺陷**，让全部四个臂的冒烟预检静默失效。
这类缺陷不会体现在任何 AP 上，只会在需要它拦住问题的那天暴露。

## 6. A3 的证据链

A3 不是 A1+A2 的直接叠加，每一项都对应上面某条结论：

```yaml
hybrid_matching:
  iou_aware_classes: [1]          # 只对行人开。第 2 节：全局开会砍掉车辆天花板 32.7%
  localisation_cost_scale_by_class: {1: 0.5}

  pool_dir: reports/epst4d_v3/seit_pool_v2   # 第 5 节缺陷 6：行人供体 400→841，序列 12→43
  probability: 1.0
  max_pedestrians_per_sample: 6   # A2 证明行人天花板 +78% 来自 SEIT，加大剂量
  max_vehicles_per_sample: 0      # 车辆天花板本就守住，粘车只带来标签噪声
  max_coverage_of_existing: 0.15  # 第 5 节缺陷 5：护住已有标注，修 A2 的排序效率损失
```

预期：行人吃到 A1 的排序增益（eff 0.102 → 0.282）与 A2 的天花板增益（1.87 → 3.33）
的乘积效应；车辆通过"不开 IoU-aware + 不粘车 + 覆盖守卫"三重保护回到 R1 水平。

## 7. 测量装置纪律（本次新踩的坑）

1. **oracle 视图会污染 model 视图的统计。** 分数截断计数器同时被 model 和 oracle
   两条路径调用，而 oracle 把置信度替换成了 3D IoU，两者混在一起使统计无意义。
   规则：任何按分数聚合的装置必须显式按视图过滤。
2. **`--train-stride` 只影响采样、不影响前向。** 用它"加速"诊断是无效的，
   一秒都省不下。真正跳过训练集通道需要 `--skip-train`（本次新增，已保留）。
3. **`pkill` 的模式会误伤刚启动的同名进程。** 应改用先查 PID 再定点 kill。
4. **`--output` 收 GPU 结果目录，传文件路径会创建出名为 `DASHBOARD.json` 的目录。**
